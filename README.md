## Design Focus

These projects are intentionally small enough to inspect but large enough to exercise real engineering tradeoffs. Across them, I am practicing:

- Turning project ideas into clear domain models and API boundaries
- Choosing where state should live across memory, queues, databases, and clients
- Separating core logic from infrastructure and presentation concerns
- Writing documentation that explains not only what the code does, but why it is shaped that way
- Improving from "it works" toward code that is easier to test, extend, and maintain

## Current Direction

I am continuing to build projects that deepen my understanding of backend architecture, service boundaries, authentication, database design, distributed workflows, and operational tooling. My goal is to steadily grow from feature implementation into stronger architectural judgment.
